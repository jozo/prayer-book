# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Catholic prayer book: Vue 3 SPA (Vite, Pinia, vue-i18n, Tailwind v4) wrapped in Capacitor for Android.
Plain JavaScript — no TypeScript. Package manager: npm. Upstream is Codeberg, not GitHub.

**`sw` means Swahili, not "service worker".** There is no service worker in this project. Commits and
changelog entries like "Add SW version" refer to the `src/prayers/sw/` language.

## Commands

- `npm run dev` — Vite dev server. `vite-plugin-watch` runs `compilePrayers.js` on start and on any
  change under `src/prayers/**/*.toml`.
- `npm run build` — `prebuild` runs `compilePrayers.js`, then `vite build` → `dist/`.
- `node compilePrayers.js` — compile prayers manually (`src/prayers` → `public`).
- `npm run lint` — ESLint 10, flat config in `eslint.config.js`. Reports only; use `npm run lint:fix`
  to auto-fix. Currently clean — keep it that way.

## Prayer content model

Source of truth is one TOML file per prayer per language: `src/prayers/{lang}/{prayerId}.toml`.

- **The filename minus `.toml` is the prayer id** (camelCase) and must match across languages —
  `litanyLoreto.toml` is the same prayer in `en/`, `es/`, `fr/`, etc.
- **Titles must be unique within a language.** `CategoryView.getPrayersFromAllCategories()` keys the
  "all" list by title, so a duplicate title silently makes one prayer disappear. This has already
  caused one bug (`5260a66`).
- `compilePrayers.js` logs and **skips** files that fail to parse or validate — a malformed TOML
  silently drops that prayer from the build rather than failing it. Check the compile output.

```toml
title = "Glory Be"
categories = ["basic"]   # basic | rosary | litany | saints | other

[[versions]]
name = ""                # "" when there is only one version
content = """ markdown """
```

`custom` and `bookmarks` are runtime-only pseudo-categories and never appear in TOML.

**Litanies:** each call and its italic response (`_Have mercy on us._`) must be separate paragraphs
separated by a blank line — CommonMark collapses single newlines. Follow the formatting in
`src/prayers/en/litanyLoreto.toml`.

**Never hand-edit `public/*.json`** — generated by `compilePrayers.js` and gitignored.

## Adding a language

1. Add the ISO 639-1 code to `Lang` in `src/constants.js`
2. Add a full message block to `src/messages.js` (keyed by lang code)
3. Create `src/prayers/{lang}/` with TOML files

## Code style

There is no Prettier. ESLint is the only formatter and it covers both `<template>` and `<script>`,
so **`npm run lint:fix` is the canonical way to format** — don't hand-format to taste.

Enforced by `@stylistic` (ESLint 10 dropped the core formatting rules), configured in
`eslint.config.js` to match this codebase:

- double quotes, semicolons, 2-space indent, no trailing commas, 1tbs braces
- **unspaced** object and import braces: `import {ref} from "vue"`, `{key: "bookmarks"}`
- object key quoting is not enforced (`@stylistic/quote-props` is off), so `{"custom": {}}` in
  `prayerDataStore.js` stays as written

Note this is the opposite of the old `.prettierrc.json` (single quotes, no semicolons), which the
source never actually followed and which has been deleted.

`vue/script-indent` handles indentation inside `.vue` files; `@stylistic/indent` is off there
because it conflicts with `vue-eslint-parser`. Templates get one attribute per line and
self-closing empty elements from `flat/recommended`.

## Known warnings (harmless)

`package.json` has no `"type": "module"` while `vite.config.js` and `eslint.config.js` are ESM, so
Node prints `MODULE_TYPELESS_PACKAGE_JSON` and Vite warns about `configLoader: 'native'`. Adding
`"type": "module"` would break `compilePrayers.js`, which is CommonJS (`require`). Fixing this means
renaming it to `compilePrayers.cjs` and updating the `prebuild` script and `vite.config.js`.

## Generated / off-limits files

- `public/*.json` — generated by `compilePrayers.js`
- `android/app/capacitor.build.gradle` — regenerated by `cap sync`/`cap update`
- `android/local.properties` — machine-local
- `src/stores/counter.js` — unused Vue scaffolding
